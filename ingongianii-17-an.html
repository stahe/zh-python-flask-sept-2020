    此新版本带来了以下更新：

    37.1. 应用程序依赖项的迁移

    需要提醒的是，应用程序依赖项的管理是在脚本 [syspath] 中进行的。在上一版本中，该脚本如下所示：

    
def configure(config: dict) -> dict:
    import os

    # 该文件的目录
    script_dir = os.path.dirname(os.path.abspath(__file__))

    # 根路径
    root_dir = "C:/Data/st-2020/dev/python/cours-2020/python3-flask-2020"

    # 依赖项
    absolute_dependencies = [
        # 项目文件夹
        # BaseEntity, MyException
        f"{root_dir}/classes/02/entities",
        # InterfaceImpôtsDao, InterfaceImpôtsMétier, InterfaceImpôtsUi
        f"{root_dir}/impots/v04/interfaces",
        # AbstractImpôtsdao, ImpôtsConsole, ImpôtsMétier
        f"{root_dir}/impots/v04/services",
        # ImpotsDaoWithAdminDataInDatabase
        f"{root_dir}/impots/v05/services",
        # AdminData, ImpôtsError, TaxPayer
        f"{root_dir}/impots/v04/entities",
        # 常量、区间
        f"{root_dir}/impots/v05/entities",
        # 记录器，SendAdminMail
        f"{root_dir}/impots/http-servers/02/utilities",
        # 主脚本文件夹
        script_dir,
        # 配置[database, layers, parameters, controllers, views]
        f"{script_dir}/../configs",
        # 控制器
        f"{script_dir}/../controllers",
        # 答案HTTP
        f"{script_dir}/../responses",
        # 视图模板
        f"{script_dir}/../models_for_views",
    ]

    # 设置 syspath
    from myutils import set_syspath

    # 生成配置

        "script_dir": script_dir

    新版本中的脚本 [syspath] 将如下所示：

    
def configure(config: dict) -> dict:
    import os

    # 此文件的目录
    script_dir = os.path.dirname(os.path.abspath(__file__))

    # 依赖项
    absolute_dependencies = [
        # 应用程序实体
        f"{script_dir}/../entities",
        # 层 [dao]
        f"{script_dir}/../layers/dao",
        # 层 [métier]
        f"{script_dir}/../layers/métier",
        # 实用程序
        f"{script_dir}/../utilities",
        # 主脚本文件夹
        script_dir,
        # 配置[database, layers, parameters, controllers, views]
        f"{script_dir}/../configs",
        # 控制器
        f"{script_dir}/../controllers",
        # 答案HTTP
        f"{script_dir}/../responses",
        # 视图模板
        f"{script_dir}/../models_for_views",
    ]

    # 设置 syspath
    import sys
    # 为其添加项目的绝对依赖项
    for directory in absolute_dependencies:
        # 检查文件夹是否存在
        existe = os.path.exists(directory) and os.path.isdir(directory)
        if not existe:
            # 向开发人员发出警告
            raise BaseException(f"[set_syspath] le dossier du Python Path [{directory}] n'existe pas")
        else:
            # 将文件夹插入 syspath 的开头
            sys.path.insert(0, directory)

    # 生成配置
    return {
        "script_dir": script_dir,
    }
    • 第 8-27 行：所有依赖项现均相对于第 5 行的变量 [script_dir]；
    • 第 42-45 行：变量 [root_dir] 已从 syspath 配置中移除；
    • 第 10 行：应用程序的实体位于 [entities] [1] 文件夹中；
    • 第12行：[dao]层位于[layers/dao]和[2]文件夹中；
    • 第 14 行：图层 [métier] 位于文件夹 [layers/métier] [2] 中；
    • 第 16 行：[Logger, SendMail] 实用程序位于文件夹 [utilities] [3] 中；
    • 第29-40行：计算应用程序的Python路径，且不导入模块[myutils]；

    37.3.2. 安装 Python 模块 mod_wsgi

    我们开发的 Python / Flask 应用程序使用了随 Flask 一起提供的 WSGI（Web Server Gateway Interface）[werkzeug] 服务器。 该服务器的介绍请见|此处|。链接[https://www.fullstackpython.com/wsgi-servers.html]介绍了WSGI服务器的运行原理。 存在多种 |WSGI| 服务器。其中之一是运行在 WSGI 模式下的 Apache 服务器。本文采用此方案，是因为我们安装的 Laragon 自带 Apache 服务器。

    为了让 Apache 服务器能够托管 Python 应用程序，我们需要安装 Python 模块 [mod_wsgi]。 该模块的安装较为复杂，因为安装过程中会进行 C++ 编译。要成功安装，需要 Microsoft C++ 编译器。一个简单的解决方案是安装最新版本的 Visual Studio Community [https://visualstudio.microsoft.com/fr/vs/community/]。

    如果除了 [mod_wsgi] 之外不需要使用 Visual Studio，可以将安装范围限定在 C++ 环境：

    安装好 C++ 编译器后，可在终端中安装 [mod_wsgi] 模块：

def index() -> tuple:
    # 重定向至 /init-session/html
    return redirect(url_for("init_session", type_response="html"), status.HTTP_302_FOUND)

    第 4 行，我们被重定向到 [init_session] 函数中的 URL。在 [configs/routes.py] 中，该函数已被关联到路径 [/do/init-session/html]：

    app.add_url_rule(f'{prefix_url}/init-session/<string:type_response>{csrftoken_param}', methods=['GET'],

    第2行，在我们的测试中，[csrftoken_param]是空字符串。该应用程序在此处不支持CSRF令牌。

    函数 [init_session] 的定义如下（configs/routes_without_csrftoken）：

    
# init-session
def init_session(type_response: str) -> tuple:
    # 执行与该操作关联的控制器
    return front_controller()

    第 4 行，开始处理 [init-session] 操作的字符串。该字符串在 [responses/HtmlResponse] 中以如下方式结束：

    
…
# 现在需要生成重定向的URL，如果需要，别忘了CSRF令牌

            csrf_token = f"/{generate_csrf()}"

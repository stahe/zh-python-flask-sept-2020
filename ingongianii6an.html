    23. 应用练习：第6版

    23.1. 简介

    现在我们回到税款计算应用程序。我们将以此为基础构建不同的Web应用程序。

    在应用练习的第 5 版中，税务部门的数据存储在数据库中。该第 5 版包含两个独立但具有共同层级的应用程序：

    • 一个以 |批处理| 模式为存储在文本文件中的纳税人计算税款的应用程序；
    • 一个通过键盘输入纳税人信息，以 |交互| 模式计算税款的应用程序；

    批处理（batch）模式的税款计算应用程序第5版具有以下架构：

    最终，该应用程序的Web版本将采用以下架构：

    • Web客户端 [1] 连接至 Web 服务器 [2]，该服务器通过 SGBD 与 [3] 进行通信；
    • Web 服务器 [2] 保留了初始应用程序中的 [métier]、[8] 以及 [dao]、[9] 层；
    • 初始应用程序保留其主脚本 [4] 及其层 [métier] 和 [15]。 [métier]、[8] 和 [15] 层完全相同；
    • 客户端/服务器通信需要两个额外层：
      • 实现 Web 应用程序的 [web] [7] 层；
      • 作为 Web 应用程序 [7] 客户端的 [dao] [5] 层；

    在最终版本中，批量税款计算可通过两种方式进行：

    • 由服务端的 [métier] 层执行业务税费计算。脚本 [main] 将采用此方法；
    • 税款业务计算由客户端的 [métier] 层完成。脚本 [main2] 将采用此方法；

    从现在开始，我们将开发多个上述类型的客户端/服务器应用程序，每个应用程序都将展示一种或多种新的Web开发技术。

    脚本 [server_01] 是以下 Web 应用程序：

    • 在 [1] 中，使用了一个已配置的 URL，其中传递三个值：
      • [marié]（是/否）用于指示纳税人是否已婚；

    • [3-8] 层是税款计算应用程序 |第 5 版| 中已使用的层。我们直接沿用这些层；

      • [dao] [4] 层在此处定义；

# 首页 URL : /?已婚=xx&子女=yy&工资=zz
@app.route('/', methods=['GET'])
def index():
    # 起初没有错误
    erreurs = []
    # URL 中的请求必须包含三个参数
    if len(request.args) != 3:
        erreurs.append("Méthode GET requise avec les seuls paramètres [marié, enfants, salaire]")

    # 从 URL 中获取婚姻状况
    marié = request.args.get('marié')
    if marié is None:
        erreurs.append("paramètre [marié] manquant")
    else:
        marié = marié.strip().lower()
        erreur = marié != "oui" and marié != "non"
        if erreur:
            erreurs.append(f"paramétre marié [{marié}] invalide")

    # 从 URL 中获取子女数量
    enfants = request.args.get('enfants')
    if enfants is None:
        erreurs.append("paramètre [enfants] manquant")
    else:
        enfants = enfants.strip()
        match = re.match(r"^\d+", enfants)
        if not match:
            erreurs.append(f"paramétre enfants [{enfants}] invalide")
        else:
            enfants = int(enfants)

    # 从 URL 中获取工资
    salaire = request.args.get('salaire')
    if salaire is None:
        erreurs.append("paramètre [salaire] manquant")
    else:
        salaire = salaire.strip()
        match = re.match(r"^\d+", salaire)
        if not match:
            erreurs.append(f"paramétre salaire [{salaire}] invalide")
        else:
            salaire = int(salaire)

    # URL中存在无效参数？
    for key in request.args.keys():
        if key not in ['marié', 'enfants', 'salaire']:
            erreurs.append(f"paramètre [{key}] invalide")

    # 是否存在错误？
    if erreurs:
        # 向客户发送错误响应
        résultats = {"réponse": {"erreurs": erreurs}}
        return json_response(résultats, status.HTTP_400_BAD_REQUEST)

    # 无错误，可以继续处理
    # 计算税款
    taxpayer = TaxPayer().fromdict({'marié': marié, 'enfants': enfants, 'salaire': salaire})
    config["layers"]["métier"].calculate_tax(taxpayer, admindata)
    # 向客户发送响应
    return json_response({"réponse": {"result": taxpayer.asdict()}}, status.HTTP_200_OK)

# 导入依赖项
import re

from flask_api import status
from werkzeug.local import LocalProxy


# URL 参数设置：/?已婚=xx&子女=yy&工资=zz
def execute(request: LocalProxy, config: dict) -> tuple:
    # 依赖项
    from TaxPayer import TaxPayer

    # 初始时无错误
    erreurs = []
    # 请求必须包含三个参数
    if len(request.args) != 3:
        erreurs.append("Méthode GET requise avec les seuls paramètres [marié, enfants, salaire]")

    # 获取 URL 的婚姻状况
    marié = request.args.get('marié')
    if marié is None:
        erreurs.append("paramètre [marié] manquant")
    else:
        marié = marié.strip().lower()
        erreur = marié != "oui" and marié != "non"
        if erreur:
            erreurs.append(f"paramétre marié [{marié}] invalide")

    # 获取 URL 的子女数量
    enfants = request.args.get('enfants')
    if enfants is None:
        erreurs.append("paramètre [enfants] manquant")
    else:
        enfants = enfants.strip()
        match = re.match(r"^\d+", enfants)
        if not match:
            erreurs.append(f"paramétre enfants {enfants} invalide")
        else:
            enfants = int(enfants)

    # 获取 URL 的工资
    salaire = request.args.get('salaire')
    if salaire is None:
        erreurs.append("paramètre [salaire] manquant")
    else:
        salaire = salaire.strip()
        match = re.match(r"^\d+", salaire)
        if not match:
            erreurs.append(f"paramétre salaire {salaire} invalide")
        else:
            salaire = int(salaire)

    # URL 中的其他参数？
    for key in request.args.keys():
        if not key in ['marié', 'enfants', 'salaire']:
            erreurs.append(f"paramètre [{key}] invalide")

    # 是否出现错误？
    if erreurs:
        # 向客户发送错误响应
        résultats = {"réponse": {"erreurs": erreurs}}
        return résultats, status.HTTP_400_BAD_REQUEST

    # 无错误，可以继续处理
    # 计算税款
    taxpayer = TaxPayer().fromdict({'marié': marié, 'enfants': enfants, 'salaire': salaire})
    config["layers"]["métier"].calculate_tax(taxpayer, config["admindata"])
    # 向客户端发送响应
    return {"réponse": {"result": taxpayer.asdict()}}, status.HTTP_200_OK

    • 第13行：[dao]层提供需计算税款的纳税人列表；
    • 第 21 行：[dao] 层计算每位纳税人的税额；
    • 第23行：结果被保存到文件jSON中；

    23.3.4. [dao] 层的实现

    让我们回顾一下所使用的客户端/服务器架构：

    • 在 [2, 6] 中，我们可以看到 [dao] 层具有两个作用：
      • 它既访问文件系统以读取纳税人的数据，也写入税款计算结果。我们已经有一个 |AbstractImpôtsDao| 类能够完成这些操作。该类自 |第 4 版| 起便已投入使用；
      • 它与 Web 服务器 [3] 进行交互；

    在 |第 5 版| 中，主脚本 [main] [1] 直接与 [métier] [4] 层进行交互。 我们希望不修改该脚本。为此，我们将确保 [dao] [2] 层实现 [métier] [4] 层的接口。 这样，主脚本 [main] 就会感觉像是在直接与 [métier] [4] 层进行交互，并完全忽略该层位于另一台机器上的事实。

    实现 [dao] [2] 层的类定义可以如下所示：

    
class ImpôtsDaoWithHttpClient(AbstractImpôtsDao, InterfaceImpôtsMétier):
    • 类 [ImpôtsDaoWithHttpClient]：
      • 继承自类 [AbstractImpôtsDao]，从而能够管理与文件系统 [6] 的交互；
      • 实现了接口 [InterfaceImpôtsMétier]，从而无需修改 |第 5 版| 的主脚本 [main]；

    [ImpôtsDaoWithHttpClient]类的完整代码如下：

    
# 导入
import requests
from flask_api import status

from AbstractImpôtsDao import AbstractImpôtsDao
from AdminData import AdminData
from ImpôtsError import ImpôtsError
from InterfaceImpôtsMétier import InterfaceImpôtsMétier
from TaxPayer import TaxPayer


class ImpôtsDaoWithHttpClient(AbstractImpôtsDao, InterfaceImpôtsMétier):

    # 构造函数
    def __init__(self, config: dict):
        # 父类初始化
        AbstractImpôtsDao.__init__(self, config)
        # 参数存储
        self.__config_server = config["server"]

    # [AbstractImpôtsDao] 的未使用方法
    def get_admindata(self) -> AdminData:
        pass

    # 税款计算
    def calculate_tax(self: object, taxpayer: TaxPayer, admindata: AdminData = None):
        # 允许异常上报
        # GET 参数
        params = {"marié": taxpayer.marié, "enfants": taxpayer.enfants, "salaire": taxpayer.salaire}
        # 使用 Basic 认证进行连接？
        if self.__config_server['authBasic']:
            response = requests.get(
                # 被查询服务器的 URL
                self.__config_server['urlServer'],
                # URL 的参数
                params=params,
                # Basic 身份验证
                auth=(
                    self.__config_server["user"]["login"],
                    self.__config_server["user"]["password"]))
        else:
            # 不使用 Basic 身份验证的连接
            response = requests.get(self.__config_server['urlServer'], params=params)
        # 验证
        print(response.text)
        # 响应状态码 HTTP
        status_code = response.status_code
        # 将响应 jSON 放入字典
        résultat = response.json()
        # 如果状态码不为 200，则报错 OK
        if status_code != status.HTTP_200_OK:
            # 已知错误已关联至响应中的键 [erreurs]
            raise ImpôtsError(87, résultat['réponse']['erreurs'])
        # 已知该结果与响应中的键 [result] 相关联
        # 使用该结果修改输入参数
        taxpayer.fromdict(résultat["réponse"]["result"])
    • 第 21-23 行：类 [AbstractImpôtsDao]（第 12 行）包含一个抽象方法 [get_admindata]。即使我们不使用它（admindata 由服务器而非客户端管理），也必须对其进行实现；
    • 第 26 行：方法 [calculate_tax] 属于接口 [InterfaceImpôtsMétier]（第 12 行）。我们需要对其进行实现；
    • 第 15 行：构造函数接收的唯一参数是应用程序配置字典；
    • 第16-17行：通过同样传入应用程序配置来初始化父类[AbstractImpôtsDao]。该类将从中获取其需要管理的三个文本文件的名称；
    • 第18-19行：在类中本地存储与税款计算Web服务器相关的信息；
    • 第26行：方法 [calculate_tax] 接收一个类型为 |Taxpayer| 的对象作为参数。为了符合方法 [InterfaceImpôtsMétier.calculate_tax] 的签名，它还接收一个参数 [admindata]，该参数旨在封装税务部门的数据。 客户端并不拥有这些数据。该参数始终保持为 [None]。这种扭曲的实现方式表明，[ImpôtsMétier] 类最初编写有误：
    • [calculate_tax] 的签名本应仅为： 
    
def calculate_tax(self, taxpayer: TaxPayer)

    ，而参数 [admindata : AdminData] 本应传递给该类的构造函数；

    • 第 27 行：方法 [calculate_tax] 的代码未封装在 try / catch / finally 块中。这意味着可能发生的异常将无法被处理，并会回传至调用方代码，即脚本 [main]。 该脚本确实捕获了从 [dao] 层回传的所有异常；
    • 第 28 行：税款计算在服务器端进行。因此需要与服务器进行通信。这通过第 2 行导入的 [requests] 模块实现；
    • 第31-43行：为向Web服务器发送GET请求，使用[requests.get]方法：
      • 第33-34行：该方法的第一个参数是要联系的URL；
      • 第35-40行：其余两个参数是命名参数，其顺序无关紧要；
      • 第35-36行：名为[params]的参数值必须是一个字典，其中包含以[/url ?param1=valeur1&param2=valeur2&…]格式写入URL中的信息；
      • 第29行：包含Web服务器所期待的三个参数[marié, enfants, salaire]的字典。无需处理这些参数必须经过的编码（称为urlencoded），[requests]会自动处理；
      • 第 37-40 行：名为 [auth] 的参数是一个包含两个元素（login、password）的元组。它代表 Basic 类型身份验证的凭据；
    • 第 44-45 行：这两行仅用于教学目的（调试完成后将注释掉）：
      • [response] 代表服务器的响应 HTTP；
      • [response.text] 代表封装在此响应中的文档文本。在调试阶段，检查服务器发送的内容非常有用；
    • 第 47 行：[response.status_code] 是接收到的响应的状态码 HTTP。我们的服务器仅发送三种状态码：
      • 200 OK
      • 400 BAD REQUEST
      • 500 INTERNAL SERVER ERROR
    • 第 49 行：即使出现错误，我们的服务器仍会发送 jSON。 函数 [response.json()] 根据接收到的字符串 jSON 创建一个字典。回顾字符串 jSON 的两种可能形式： 
    
{"réponse": {"erreurs": ["Méthode GET requise avec les seuls paramètres [marié, enfants, salaire]", "paramètre [marié] manquant", "paramètre [enfants] manquant", "paramètre [salaire] manquant"]}}

    {"réponse": {"result": {"id": 0, "marié": "oui", "enfants": 3, "salaire": 200000, "impôt": 42842, "surcôte": 17283, "taux": 0.41, "décôte": 0, "réduction": 0}}}
    • 第 51-53 行：如果状态码不是 200，则抛出异常，并将错误消息封装在响应中；
    • 第 56 行：获取税额计算生成的字典，并将其用于更新输入参数 [taxpayer]；

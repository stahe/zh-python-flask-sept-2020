    24. 应用练习：第7版

    24.1. 简介

    税款计算应用程序的第7版与第6版基本相同，仅在以下细节上有所不同：

    • Web客户端将同时发起多个HTTP请求。在上一版本中，这些请求是顺序发起的。因此，服务器在任何时刻都只处理一个请求；
    • 服务器将采用多线程架构：能够同时处理多个请求；
    • 为跟踪这些请求的执行情况，我们将为Web服务器配备一个日志记录器，用于将请求处理过程中的关键时刻记录到文本文件中；
    • 当服务器遇到导致无法启动的问题时（通常是与Web服务器关联的数据库问题），将向应用程序管理员发送一封邮件；

    24.2.1. 类 [Logger]

    类 [Logger] 用于将 Web 服务器的某些操作记录到文本文件中：

    
import codecs
import threading
from datetime import date, datetime
from threading import current_thread

from ImpôtsError import ImpôtsError


class Logger:
    # 类属性
    verrou = threading.RLock()

    # 构造函数
    def __init__(self, logs_filename: str):
        try:
            # 以追加模式（a）打开文件
            self.__resource = codecs.open(logs_filename, "a", "utf-8")
        except BaseException as erreur:
            raise ImpôtsError(18, f"{erreur}")

    # 写入日志
    def write(self, message: str):
        # 当前日期/时间
        today = date.today()
        now = datetime.time(datetime.now())
        # 线程名称
        thread_name = current_thread().name
        # 在向日志文件写入数据期间不希望被打断
        # 请求类的同步对象（即锁）——仅有一个线程能获得它
        Logger.verrou.acquire()
        try:
            # 写入日志
            self.__resource.write(f"{today} {now}, {thread_name} : {message}")
            # 立即写入——否则文本仅会在关闭写入流时写入
            # 但我们希望能够追踪日志随时间的变化
            self.__resource.flush()
        finally:
            # 释放同步对象（即锁），以便其他线程能够获取它
            Logger.verrou.release()

    # 释放资源
    def close(self):
        # 关闭文件
        if self.__resource:
            self.__resource.close()

    • 第 14-19 行：构造函数接收日志文件的绝对路径。随后打开该文件，并将获取的文件描述符存储在类中；
    • 第 17 行：日志文件以“追加”模式（a）打开。每行写入的内容都将追加到文件末尾；
    • 第22-39行：方法[write]用于将作为参数传递的消息写入日志文件。该消息后附有两项信息：
      • 第24行：当前日期；
      • 第25行：当前时间；
      • 第 27 行：写入日志的线程名称。这里需要注意的是，Web 应用程序同时为多个用户提供服务。每个请求都会被分配一个线程来执行。如果该线程被暂停（通常是由于 I/O 操作，如网络、文件或数据库操作），则处理器资源将分配给另一个线程。 由于可能发生此类中断，我们无法确保某个线程能在不受干扰的情况下成功向日志文件写入一行内容。因此，可能会出现两个不同线程的日志混杂在一起的情况。虽然这种风险很小，甚至可能为零，但我们还是决定演示如何同步两个线程对共享资源（此处为日志文件）的访问；
    • 第30行：在写入之前，线程请求入口门的钥匙。所请求的钥匙即第11行创建的那个。它确实是唯一的：类属性对该类的所有实例而言都是唯一的；
      • 在时间戳 T1 时，线程 Thread1 获取了钥匙。随后它即可执行第 33 行代码；
      • 在时间戳 T2 时，线程 Thread1 在完成日志写入之前就被暂停；
      • 在时间戳 T3 时，获得处理器资源的 Thread2 线程也需要写入日志。它运行到第 30 行时，请求获取入口门的钥匙。系统返回响应称另一条线程已持有该钥匙。于是它被自动暂停。所有请求该钥匙的线程都会经历同样的情况；
      • 在时间点 T4，此前被暂停的线程 Thread1 重新获得处理器。随后它完成了日志的写入；
    • 第32-36行：日志文件的写入分为两个步骤：
    • 第33行：第17行获取的文件描述符使用缓冲区。第33行的操作[write]将数据写入该缓冲区，而非直接写入文件。随后在特定条件下，缓冲区中的数据会被写入文件：
          • 缓冲区已满；
          • 文件描述符执行了 [close] 或 [flush] 操作；
    • 第36行：强制将日志行写入文件。 这样做的目的是为了观察不同线程的日志是否交错记录。如果不这样做，当关闭文件描述符（第45行）时，某个线程的所有日志都会被同时写入。届时将很难察觉某些线程已被终止：必须通过查看日志中的时间戳来判断；
    • 第39行：Thread1线程归还了之前分配给它的锁。该锁将能够分配给另一个线程；
    • 第22行：因此方法[write]是同步的：每次仅允许一个线程向日志文件写入数据。关键点在于第30行：无论发生什么情况，只有一个线程能获取进入下一行的通行密钥。该线程会一直持有该密钥，直到将其归还（第39行）；
    • 第 41-45 行：方法 [close] 用于释放分配给日志文件描述符的资源；

        # 邮件由 config['from'] 发送

        # 邮件主题为 config['subject']

        logger = config["logger"]

        server = None
        # 发送消息
        try:
            # 服务器 SMTP
            server = smtplib.SMTP(config["smtp-server"])
            # 详细模式
            server.set_debuglevel(verbose)
            # 安全连接？
            if config['tls']:
                # 开始安全对话
                server.starttls()
                # 身份验证
                server.login(config["user"], config["password"])

            msg['To'] = config["to"]
            msg['Date'] = formatdate(localtime=True)
            msg['Subject'] = config["subject"]
            # 发送消息
            server.send_message(msg)
            # 日志 - 日志记录器可能不存在
            if logger:
                logger.write(f"[SendAdminMail] Message envoyé à [{config['to']}] : [{message}]\n")
        except BaseException as erreur:
            # 日志 - 日志器可能不存在
            if logger:
                logger.write(
                    f"[SendAdminMail] Erreur [{erreur}] lors de l'envoi à [{config['to']}] du message [{message}] : \n")
        finally:
            # 操作完成 - 释放函数占用的资源

                server.quit()

# 首页 URL
@app.route('/', methods=['GET'])
@auth.login_required
def index():
    logger = None
    try:
        # 记录
        logger = Logger(config["logsFilename"])
        # 将其存储在与线程关联的配置中
        thread_config = {"logger": logger}
        thread_name = threading.current_thread().name
        config[thread_name] = {"config": thread_config}
        # 记录请求
        logger.write(f"[index] requête : {request}\n")
        # 如果收到请求，则中断线程
        sleep_time = config["sleep_time"]
        if sleep_time != 0:
            # 暂停是随机的，以便某些线程被中断而其他线程不被中断
            aléa = randint(0, 1)
            if aléa == 1:
                # 暂停前进行日志记录
                logger.write(f"[index] mis en pause du thread pendant {sleep_time} seconde(s)\n")
                # 暂停
                time.sleep(sleep_time)
        # 由控制器执行该请求
        résultat, status_code = index_controller.execute(request, config)
        # 是否发生了致命错误？
        if status_code == status.HTTP_500_INTERNAL_SERVER_ERROR:
            # 向应用程序管理员发送邮件
            config_mail = config["adminMail"]
            config_mail["logger"] = logger
            SendAdminMail.send(config_mail, json.dumps(résultat, ensure_ascii=False))
